# OTUS Dating App Monolith

Монолитное приложение dating-сервиса, реализованное на основе OpenAPI спецификации для курса OTUS Highload Architect.

## Описание

Это минимальный прототип dating-приложения с функциональностью:
- Регистрация и аутентификация пользователей
- Управление профилями пользователей
- Система друзей (добавление/удаление)
- Система постов с лентой новостей
- **Диалоги между пользователями** (ключевая функциональность)

## Технический стек

- **Backend**: NestJS 11 (TypeScript)
- **База данных**: SQLite с TypeORM
- **Аутентификация**: JWT Bearer Token
- **Документация**: Swagger/OpenAPI
- **Контейнеризация**: Docker

## Установка и запуск

### Локальный запуск

```bash
# Установка зависимостей
$ npm install

# Запуск в режиме разработки
$ npm run start:dev

# Сборка проекта
$ npm run build

# Запуск в production режиме
$ npm run start:prod
```

Приложение будет доступно по адресу: http://localhost:3000

Swagger документация: http://localhost:3000/api

### Запуск через Docker

```bash
# Сборка Docker образа
docker build -t dating-app-monolith .

# Запуск контейнера
docker run -p 3000:3000 dating-app-monolith
```

## API Эндпоинты

### Аутентификация
- `POST /user/register` - Регистрация нового пользователя
- `POST /login` - Аутентификация пользователя

### Пользователи
- `GET /user/get/{id}` - Получение анкеты пользователя
- `GET /user/search` - Поиск пользователей по имени и фамилии

### Друзья
- `PUT /friend/set/{user_id}` - Добавить в друзья
- `PUT /friend/delete/{user_id}` - Удалить из друзей

### Посты
- `POST /post/create` - Создать пост
- `PUT /post/update` - Обновить пост
- `PUT /post/delete/{id}` - Удалить пост
- `GET /post/get/{id}` - Получить пост
- `GET /post/feed` - Получить ленту постов друзей

### Диалоги (ключевая функциональность)
- `POST /dialog/{user_id}/send` - Отправить сообщение пользователю
- `GET /dialog/{user_id}/list` - Получить историю диалога с пользователем

## Тестирование

### Postman коллекция

В проекте есть файл `postman-collection.json` с готовой коллекцией для тестирования всех эндпоинтов.

Импортируйте коллекцию в Postman и выполните запросы в следующем порядке:
1. **Register User** - регистрация первого пользователя
2. **Register Second User** - регистрация второго пользователя  
3. **Login** - аутентификация первого пользователя
4. **Add Friend** - добавление второго пользователя в друзья
5. **Send Message** - отправка сообщения
6. **Get Dialog Messages** - получение истории диалога

### Ручное тестирование

```bash
# Регистрация пользователя
curl -X POST http://localhost:3000/user/register \
  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Иван",
    "second_name": "Иванов", 
    "birthdate": "1990-01-01",
    "biography": "Программист",
    "city": "Москва",
    "password": "password123"
  }'

# Аутентификация
curl -X POST http://localhost:3000/login \
  -H "Content-Type: application/json" \
  -d '{
    "id": "USER_ID_FROM_REGISTRATION",
    "password": "password123"
  }'
```

## Структура проекта

```
src/
├── auth/           # Модуль аутентификации
├── users/          # Модуль пользователей
├── posts/          # Модуль постов
├── dialogs/        # Модуль диалогов (ключевая функциональность)
├── entities/       # TypeORM сущности
├── dto/           # Data Transfer Objects
└── decorators/    # Кастомные декораторы
```

## Особенности реализации

### Диалоги
- Автоматическое создание диалога при отправке первого сообщения
- Получение полной истории переписки между двумя пользователями
- Сортировка сообщений по времени создания

### База данных
- Используется SQLite для упрощения развертывания
- Автоматическая синхронизация схемы (synchronize: true)
- Связи между сущностями через TypeORM

### Безопасность
- JWT токены для аутентификации
- Хеширование паролей с помощью bcrypt
- Валидация входящих данных
