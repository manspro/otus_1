# Dialog Service - Микросервис диалогов

Отдельный микросервис для обработки диалогов и сообщений, выделенный из монолитного приложения.

## Описание

Dialog Service - это независимый NestJS микросервис, который обрабатывает только функциональность диалогов:
- Отправка сообщений между пользователями
- Получение истории диалогов
- Получение списка всех диалогов пользователя

## Технический стек

- **Framework**: NestJS 11
- **Database**: SQLite (в памяти для демонстрации)
- **Language**: TypeScript
- **Documentation**: Swagger/OpenAPI
- **Containerization**: Docker

## API Endpoints

### Отправка сообщения
```
POST /dialog/{user_id}/send
Headers: x-user-id: {sender_id}
Body: { "text": "Текст сообщения" }
```

### Получение диалога с пользователем
```
GET /dialog/{user_id}/list
Headers: x-user-id: {current_user_id}
```

### Получение всех диалогов пользователя
```
GET /dialog/list
Headers: x-user-id: {user_id}
```

### Swagger документация
```
GET /api
```

## Запуск

### Локально
```bash
cd dialog-service
npm install
npm run start:dev
```

### Docker
```bash
docker build -t dialog-service .
docker run -p 3001:3001 dialog-service
```

### Docker Compose (из корня проекта)
```bash
docker compose up dialog-service
```

## Особенности архитектуры

1. **Независимость**: Сервис полностью автономен и не зависит от других сервисов
2. **Простая аутентификация**: Использует заголовок `x-user-id` (в продакшене заменить на JWT)
3. **In-memory database**: SQLite в памяти для простоты демонстрации
4. **Swagger документация**: Автоматически генерируемая документация API

## Отличия от монолита

| Аспект | Монолит | Dialog Service |
|--------|---------|----------------|
| Функциональность | Все возможности приложения | Только диалоги |
| Аутентификация | JWT токены | Заголовок x-user-id |
| База данных | SQLite файл | SQLite в памяти |
| Порт | 3000 | 3001 |
| Размер | ~50MB образ | ~30MB образ |

## Преимущества микросервисной архитектуры

1. **Изоляция**: Проблемы в диалогах не влияют на другие функции
2. **Масштабирование**: Можно масштабировать только диалоги независимо
3. **Технологическая свобода**: Можно использовать другие технологии для диалогов
4. **Команды**: Разные команды могут работать над разными сервисами
5. **Деплой**: Независимые релизы и обновления

## Мониторинг

Сервис запускается на порту 3001 и логирует все операции в консоль.
